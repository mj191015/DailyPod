# TechTest 실기기 테스트 체크리스트

AirPods 습관 코치 앱의 핵심 기술이 되는지 확인하는 검증용 앱입니다.
앱을 열면 메뉴에 **Test A / B / C**와 **1차 알람 (AlarmKit)** 이 있습니다. 통과/실패 칸에 ✅ / ❌ 와 메모를 적어 주세요.

- 기기: iPhone 15 Pro Max / iOS 26.6.2, 에어팟 모델: ______________
- 날짜: ______________  앱 Bundle ID: `com.woowoong.techtest`
- 모든 로그 파일은 앱 Documents에 저장됩니다. 아이폰 **파일 앱 > 나의 iPhone > TechTest**에서 보이고,
  맥에서는 아래 명령으로 가져옵니다.

```bash
xcrun devicectl device copy from --device <기기 UDID> --domain-type appDataContainer \
  --domain-identifier com.woowoong.techtest --source Documents --destination ./logs
```

> 통과 기준은 **제안값**입니다. 팀에서 기준을 정했다면 그 값으로 바꿔 쓰세요.

## 시작 전 공통 준비

1. [ ] 아이폰이 맥에 연결돼 있고 잠금이 풀려 있다 (앱 설치·실행은 맥에서 함)
2. [ ] 에어팟이 이 아이폰에 연결돼 있고 귀에 착용했다
3. [ ] 앱을 처음 열 때 뜨는 **모션 권한 팝업을 허용**했다
4. [ ] 설정 > 일반 > VPN 및 기기 관리에서 개발자 앱을 신뢰했다

## 테스트 A. 백그라운드에서도 센서가 들어오는가

앱 메뉴 **Test A: Background sensor**. 위쪽 스위치로 모드를 고릅니다.

| 모드 | 의미 |
|---|---|
| Mode 1: none | 백그라운드 모드 없음 (오디오 세션·재생을 시작하지 않음) |
| Mode 2: audio | 오디오 세션(.playback) + 무음 오디오 반복 재생 |
| Mode 3: audio+resume | 모드 2 + 오디오 인터럽션 로그와 재개 시도 |
| Mode 4: loc low | **오디오 없음.** 위치 백그라운드 업데이트(정확도 낮음, 3 km)로 앱을 살려 둠 |
| Mode 5: loc best | **오디오 없음.** 위치 백그라운드 업데이트(GPS 최고 정확도)로 앱을 살려 둠 |

> 참고: `UIBackgroundModes=audio, location` 은 Info.plist에 모든 모드 공통으로 선언돼 있습니다(plist는 실행 중에 바꿀 수 없음).
> 모드 1은 아무것도 시작하지 않을 뿐이라, "선언 자체가 없는 앱"과 완전히 같지는 않을 수 있습니다.
> 모드 4, 5는 **위치 권한 팝업**이 뜹니다(허용). 화면 위쪽에 파란 위치 표시가 생기고 배터리를 더 씁니다.
> 에어팟이 맥북 등 **다른 기기로 넘어가면** 센서가 끊깁니다. 테스트 중에는 맥북 Bluetooth를 끄세요.

각 모드마다 아래를 **순서대로** 합니다.

1. [ ] 모드를 고르고 **Start**를 누른다. 화면에서 `samples`가 올라가고 `since last sample`이 0에 가깝다
2. [ ] 홈 화면으로 나간다 (홈 제스처). 시작 시각: ________
3. [ ] 10분 방치 (화면 잠금도 한 번 눌러 본다)
4. [ ] 앱을 다시 열어 `since last sample` 값과 `samples` 증가 여부를 본다
5. [ ] **Stop**을 누른다
6. [ ] 같은 모드로 한 번 더, 이번에는 **30분** 방치한다

로그 가져온 뒤 분석:

```bash
python3 tools/analyze_bgtest.py logs/bgtest_mode*_[0-9].csv   # 시작·종료 시각까지 포함해 공백을 셉니다
```

| 모드 | 10분: 1초 초과 공백 횟수 / 총 공백(s) | 30분: 1초 초과 공백 횟수 / 총 공백(s) | 통과/실패 | 메모 |
|---|---|---|---|---|
| 1 | | | | |
| 2 | | | | |
| 3 | | | | |
| 4 | | | | |
| 5 | | | | |

**지금까지 로그로 확인된 결과 (참고, 맥북 Bluetooth 끈 상태)**

| 모드 | 확인된 것 |
|---|---|
| 1 | 백그라운드 진입 0.3초 만에 센서 끊김 |
| 2 | 홈+잠금 약 9분 39초, 공백 0 (샘플 28,827개). 30분은 미확인 |
| 3 | 약 2분 45초, 공백 0. 인터럽션(전화·시리)은 발생하지 않아 재개 로직은 미확인 |
| 4 | 약 3분 뒤 센서가 끊기고 돌아오지 않음 (10분 테스트 실패) |
| 5 | 약 9분 27초, 3.3초 멈춤 1번 후 계속 들어옴. 30분과 배터리는 미확인 |

제안 기준: 공백이 없거나 1~2초 이내 → 통과, 수십 초 이상 이어지는 공백이 있으면 실패.

앱 메뉴 **Test B: Stretch matching**. 녹화는 3초 카운트다운 뒤 10초간 진행됩니다.

1. [ ] **Record reference**: 정확한 스트레칭 동작을 1회 녹화한다 (`Reference saved` 확인)

3. [ ] 라벨을 **Other motion** 으로 바꾸고 **다른 동작 5회**: 한쪽만 기울임 / 가만히 / 고개 꾸벅 등

4. [ ] 시도마다 화면에 `simple` / `dtw` 값이 나온다

## 테스트 C. 알림 소리가 의도대로 나는가

앱 메뉴 **Test C: Alert sound**. 화면 가운데에 현재 오디오 출력 경로가 표시됩니다.

- **1차**: `Stage 1 alert` 버튼 → 소리 10초 → 자동 정지 → 3초 공백 → 곧바로 2차 시작
- **2차**: `Stage 2 alert` 버튼 → `Stop`을 누를 때까지 반복
- 비교용: `Local notification in 5 s` (소리 포함 로컬 알림, 처음에는 알림 권한 팝업이 뜸)

아래 칸을 하나씩 채웁니다. 에어팟으로 소리가 나는지(출력 경로에 에어팟이 표시되는지)도 함께 봅니다.

| 상태 | 1차: 10초 뒤 자동 정지 | 1차: 3초 공백 후 2차 자동 시작 | 2차: 반복 재생 | 2차: Stop으로 중지 | 출력 경로 |
|---|---|---|---|---|---|
| 앱 화면 켠 상태 | | | | | |
| 홈으로 나간 상태 | | | | | |
| 화면 잠금 상태 | | | | | |
| 무음 스위치 켠 상태 | | | | | |
| 집중 모드 켠 상태 | | | | | |

방법: 버튼을 누른 직후 **홈으로 나가기 / 화면 잠금**을 한다 (각 상태에서 1차와 2차 모두).
무음 스위치·집중 모드는 화면을 켠 채로 한 번씩 확인한다.

- [ ] 로컬 알림(5초 뒤): 앱 화면 켠 상태에서 소리 ______ / 홈 ______ / 잠금 ______ / 무음 스위치 ______ / 집중 모드 ______
- 로그 `alerttest_*.csv` 에서 `stage1 start`, `stage1 end`, `gap over`, `stage2 start` 시각 차이가 10초 / 3초에 가까운가: ______
  (잠금 상태에서 공백 후 `stage2 start` 가 늦거나 없으면, 3초 공백 중 앱이 멈춘 것입니다.)

## 테스트 D. 1차 알람 (AlarmKit)

앱 메뉴 **1차 알람 (AlarmKit)**. iOS 26.1 이상에서만 동작합니다. 시스템이 알람 화면을 띄웁니다.

1. [ ] **10초 뒤 알람**을 누른다 (처음에는 알람 권한 팝업 → 허용)
2. 아래 세 상태에서 각각 확인한다.

| 상태 | 알람 화면이 뜬다 | X 버튼이 보인다 | X를 누르면 꺼진다 | 안 누르면 10초 뒤 꺼진다 | 메모 |
|---|---|---|---|---|---|
| 앱을 켜 둔 상태 (빨간 전체 화면 + 작은 X) | | | | | |
| 홈 화면 (위쪽 작은 배너) | | | | | |
| 화면 잠금 (화면이 켜지면서 큰 알람 화면) | | | | | |

알아 둘 점 (문서와 실제 확인):
- 시스템 기본 끄기(잠금 화면의 "밀어서 중단")는 **없앨 수 없습니다.** X 버튼은 그 옆에 추가되는 버튼입니다.
- 홈 화면에서는 시스템이 **작은 배너**로만 보여 주며, 앱이 큰 화면으로 바꿀 수 없습니다.
- 앱을 켜 둔 상태의 빨간 전체 화면은 이 화면을 열어 둔 동안에만 뜹니다.
- 10초 뒤 자동 꺼짐은 앱이 시스템에 "꺼 달라"고 요청하는 방식이라 앱이 살아 있어야 합니다.

로그: `xalarmkit_*.csv`(상태와 X 누른 시각), `xalarmkit_intent.csv`(알람 화면의 X 버튼이 실행됐는지).
